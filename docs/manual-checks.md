# Что осталось проверить с аккаунтом

## OTP

1. Откройте `http://localhost:8088` и нажмите «Войти».
2. Войдите как `prothetic1`. Пароль — значение `DEMO_PASSWORD` в локальном `.env`.
3. Привяжите Google Authenticator или FreeOTP, введите код и название устройства. Код и QR не добавляйте в Git или отчёт.
4. После возврата в приложение скачайте отчёт за предыдущие полные дни.
5. Выйдите и войдите снова. Убедитесь, что без OTP вход невозможен, а верный код открывает приложение.

Это синтетический пользователь учебного стенда, не личный аккаунт.

## Яндекс ID

1. В своём аккаунте создайте приложение в [Яндекс OAuth](https://oauth.yandex.ru/client/new).
2. Укажите callback `http://localhost:8088/realms/reports-realm/broker/yandex/endpoint` и права `login:info`, `login:email`. Если интерфейс требует внешний HTTPS-адрес, сначала нужно согласовать домен и TLS; не используйте случайный публичный туннель с медицинскими данными.
3. Добавьте `YANDEX_CLIENT_ID` и `YANDEX_CLIENT_SECRET` в локальный `.env`. Не присылайте секрет в чат и не публикуйте файл.
4. Выполните `.venv/bin/python scripts/keycloak.py yandex`.
5. Нажмите «Войти через Яндекс ID», пройдите вход, связывание профиля и OTP. Подтвердите использование профиля только если согласны. При отказе приложение не должно записывать прикладной профиль.
6. Проверьте наличие строки в региональной таблице `profiles` после согласия. Для нового реального аккаунта отчётов не будет, пока сотрудник не свяжет его `sub` с принадлежащим ему протезом. Не назначайте владение только по email и не подставляйте чужой идентификатор.
7. Обновите экспорт командой `.venv/bin/python scripts/keycloak.py export`. Скрипт удаляет учётные данные пользователей и заменяет секреты переменными окружения.

Настоящий вход через Яндекс ID ещё не проверен. Выключенный провайдер в шаблоне нельзя считать выполненной интеграцией.
