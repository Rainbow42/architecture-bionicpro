# Вход через Яндекс ID

Проверила вход с настоящим аккаунтом: после Яндекс OAuth и настройки OTP браузер вернулся в BionicPRO и показал имя вошедшего пользователя. После согласия на использование профиля в базе `profiles` появилась одна строка для этого пользователя.

Дополнительно проверила состояние локального стенда через Keycloak Admin CLI и запросы `SELECT count(*)` к PostgreSQL:

- Учётная запись включена и связана с провайдером `yandex`.
- OTP настроен, незавершённых обязательных действий нет.
- Профиль и отметка согласия сохранены.
- Роль `prothetic_user` не назначена, привязанных протезов нет.

Попытка скачать отчёт показала «Роль не даёт доступа к отчётам». Для новой учётной записи это ожидаемый отказ, а не ошибка входа. Вход через внешний провайдер не должен автоматически выдавать права на отчёты или привязывать чужой протез. Доступ тестового пользователя к собственному отчёту проверяется отдельно.

Экспорт `keycloak/keycloak-results-export.json` обновлён с работающего стенда: провайдер включён, значения client ID и client secret заменены переменными, пользовательские учётные данные исключены. Личный профиль, токены и OTP-секреты в репозиторий не добавлены.

Эта проверка не подтверждает cache HIT в CDN и доступ к отчётам через Яндекс ID: у проверенного аккаунта нет роли и учебных данных.
