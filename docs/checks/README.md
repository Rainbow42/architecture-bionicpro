# Проверки

Здесь сохраняется фактический вывод команд. Учебный стенд запущен через Podman Compose на ARM64; исходный `docker-compose.yaml` не требует Docker-specific API.

`check_reports.py` проверяет живые ClickHouse и MinIO после настоящего Airflow DAG, но задаёт идентификатор пользователя в тестовом процессе. Это не сквозная проверка входа. Отдельно проверен вход из браузера через настоящую сессию Keycloak после пользовательской настройки OTP и скачивание отчёта. Проверка настоящего входа через Яндекс ID описана в [yandex.md](yandex.md).

Пароли, токены, OTP-секреты и QR настройки второго фактора сюда не входят.

Подтверждены: 24 модульных теста, сборка React, аудит зависимостей фронтенда и API, импорт realm и LDAP-роли, обязательность OTP в конфигурации, успешные DAG `reports_batch` и `reports_cdc`, CDC INSERT/UPDATE/DELETE, отчёты из настоящих ClickHouse и MinIO, кеш-попадание без запроса OLAP, ответ 401 анонимному запросу CDN и `nginx -t`.

В `tests/test_oidc.py` проверяются подписанные ID/access tokens, отклонение токена без `sub`, с неверными audience, issuer, nonce, владельцем или истёкшим сроком. Отдельный тест проверяет наличие `basic` в шаблоне и живом экспорте Keycloak. Без этого scope Keycloak не добавлял `sub` в access token, и callback корректно отклонял вход. Проверки JWT не ослаблялись.

Результат новых тестов — `oidc.txt`. После пользовательской настройки OTP проверены вход через сессию Keycloak, скачивание JSON с отчётом и перезагрузка страницы спустя более 120 секунд без повторного входа. Состояние приложения после обновления токена — [browser-login.png](browser-login.png). Cache HIT в CDN, запрет чужого отчёта и доступа после выхода ещё нужно проверить через живую пользовательскую сессию.
